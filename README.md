# רצף

עורך וידאו בדפדפן לעריכה ידנית של סרטונים קצרים (בערך עד 4 דקות) לפני העלאה ליוטיוב. אין שרת: המדיה, הפרויקט והייצוא נשארים במחשב.

הממשק בעברית וכיוונו מימין לשמאל. ציר הזמן עצמו נע משמאל לימין, כמו בעורכי וידאו. כתוביות בעברית מצוירות עם הגופן Heebo וכיוון RTL.

## הרצה מקומית

```bash
npm install
npm run dev
```

שרת הפיתוח עולה על [http://127.0.0.1:43123](http://127.0.0.1:43123).

```bash
npm test
npm run build
npm run preview
```

`npm run build` יוצר אתר סטטי בתיקייה `dist/`.

## מה יש בגרסה הזו

- ייבוא וידאו, שמע ותמונות מהמחשב, כולל גרירה לספרייה או ישר לציר. כפתור «טעינת מדיה לדוגמה» מכניס קבצים קצרים שמגיעים עם הפרויקט.
- ציר עם שני מסלולי וידאו, מסלול טקסט ושני מסלולי שמע. אפשר להזיז קליפים, לקצץ קצוות, לפצל בנקודת הניגון, למחוק, ולהצמיד לקצוות ולראש הניגון.
- נגן מסונכרן: ניגון והשהיה, גרירה על סרגל הזמן, זום, וקיצורים.
- כתוביות: טקסט, גודל, צבע, מיקום, התחלה וסיום, ועמעום. אפשר גם לגרור את הכתובית על התצוגה.
- עוצמה ופייד אין / פייד אאוט לכל קליפ מדיה. עמעום של וידאו משנה גם שקיפות וגם את השמע שלו.
- שמירה אוטומטית ב-IndexedDB, וגם הורדה וטעינה של קובץ `.retzef.json`. הקובץ שומר את העריכה; הקבצים עצמם נשארים בדפדפן.
- ייצוא MP4 ליוטיוב: H.264 High (אם הדפדפן תומך), AAC-LC, 1920×1080, 30fps, כ-8 Mbps, עם `faststart` כדי שהקובץ יתחיל לנגן לפני שהוא נטען עד הסוף.

## למה WebCodecs ו-Mediabunny, ולא ffmpeg.wasm

ייצוא של כמה דקות ב-1080p צריך לקודד מאות מגה-בייט של וידאו. `ffmpeg.wasm` מריץ את FFmpeg ב-WebAssembly: הגרסה החד-חוטית איטית, והגרסה הרב-חוטית דורשת `SharedArrayBuffer` ולכן כותרות `Cross-Origin-Opener-Policy` ו-`Cross-Origin-Embedder-Policy` על השרת. זה מסבך פריסה סטטית, ועלול להיכשל בזיכרון על סרטון של כמה דקות.

[Mediabunny](https://mediabunny.dev/) מקודד דרך WebCodecs: פענוח וקידוד H.264/AAC בדפדפן, בדרך כלל עם האצה של המערכת, בלי כותרות מיוחדות. הפריימים מורכבים על canvas (וידאו, תמונות וכתוביות) ונכנסים ל-MP4. השמע ממוזג ב-Web Audio ואז מקודד ל-AAC. זה מתאים לכרום ולאדג'. ספארי ופיירפוקס עדיין לא מציעים את אותה תמיכה בקידוד AAC/AVC, והייצוא שם ייכשל עם הודעה בעברית.

## פריסה

האתר סטטי. אחרי `npm run build` מעלים את `dist/` לכל מארח סטטי:

- Netlify או Cloudflare Pages: פקודת בנייה `npm run build`, תיקיית פרסום `dist`.
- GitHub Pages: אותו דבר. אם האתר לא בשורש הדומיין, מגדירים `base` ב-`vite.config.ts`.
- שרת מקומי: `npx serve dist`.

אין צורך ב-COOP/COEP. אין משתני סביבה.

## מגבלות

- הייצוא דורש Chrome או Edge.
- סרטון של 4 דקות ב-1080p נשמר בזיכרון עד סגירת הקובץ (בערך כמה מאות מגה-בייט). מעל 10 דקות הייצוא נחסם.
- קובץ ה-JSON לא כולל את המדיה. במחשב אחר צריך לייבא את הקבצים מחדש; הקליפים יישארו «מדיה חסרה» עד אז.
- אין מעברים מלבד פייד, אין שינוי מהירות, אין חיתוך מסגרת, ואין מסלולי טקסט נוספים.
- ערבוב עברית ואנגלית באותה שורה תלוי ב-bidi של הקנבס בדפדפן.
